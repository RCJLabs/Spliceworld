# data/yearbook.json

The Yearbook (ROADMAP §9, R112): the Dex tab that shows every counter the save keeps, and the data file that decides what those rows are.

WHY THIS EXISTS. The save has carried about twenty lifetime tallies since M0 and rendered exactly one of them. `warRecord` is on the War Room's econ row; `chimeraCount`, `ranch.animalCount`, `inventory.tokenCount`, `sparCount`, `campaign.contestCount`, `campaign.breakoutCount`, `campaign.opCount`, `campaign.raidCount`, `raidsHeld`, `leviedTotal`, `notorietyPeak`, `resequenceCount`, `renderCount`, `cardCount`, `vatCount`, `rushCount` and `sentCount` were written faithfully every session and shown to nobody. A measured 180-day walk ends holding 1,853 chimeras made, 1,992 animals raised, 21,745 parts extracted and $445k levied, and the player could not see one of those numbers. A counter nobody can read is not a reward, it is a serialization cost.

THE ROWS ARE HERE, NOT IN THE ENGINE. `save/yearbook.js` is a loop over this file. A row names a dotted `from` path into the save and a `fmt`, and the module resolves and formats it; adding a counter to the screen is one object here and no code at all. That is CLAUDE.md's rule — if content needed an engine edit, the engine would be wrong — and the gate in `tools/smoke.js` enforces the other direction: every non-clock counter in `newGameState` must be covered by a `from` in this file, or be gone from the save. A counter that arrives without a row fails the commit that adds it.

A `from` IS A PREFIX, WHICH IS WHY `warRecord` IS ONE ROW AND NOT TWO. The gate credits a leaf to any row whose `from` is the leaf's path or a prefix of it, so `{ "from": "warRecord", "fmt": "record" }` covers `warRecord.wins` and `warRecord.losses` together, and reads as "922W–42L" rather than as two numbers a player has to pair up.

`derive` IS THE ONE THING THAT STILL COSTS AN ENGINE EDIT, deliberately. Days played, the longest-serving chimera and the most-used part are not stored anywhere — they are computed from the save. A statistic nobody has computed yet is a computation and not content, so a row may `derive` only a name `save/yearbook.js` offers, and smoke asserts every `derive` in this file resolves. A typo is a red gate rather than a row that reads "—" forever.

`headline` IS WHAT THE RUN BOUNDARY HAS ROOM FOR. R102's "Relocate the lab" confirmation used to list five things you were currently holding — two chimeras, three animals, two nodes — which says what is on the shelf and not what the run WAS. It now prints the rows marked `headline` here, so the sentence a player reads before ending a run grows when a counter does, and `save/slots.js` has no list of its own to drift.

WHAT IS NOT IN HERE. Dials — funds, pen capacity, notoriety, heat, facility tiers, the two device settings — are readings that fall as well as rise, and every one of them is already on a screen. They are exempt in the gate's own `DIALS` table, each with the screen that shows it written beside it, because an exemption nobody has to justify is how a list becomes a dumping ground. `spliceCount` was the third case: declared at M0, written by nothing, serialized for forty-two milestones. Migration 58 deletes it. That is the "or gone" half of R112's criterion, and it is the only migration in the table that removes a field — safe precisely because the field provably never held anything.

TONE. These are the numbers a villain shows off. The section blurbs and row subs are the boast; the numbers are the evidence. Zero death language, per CLAUDE.md: chimeras are made, animals are raised, raids are held, and the shelf gets cleared.
