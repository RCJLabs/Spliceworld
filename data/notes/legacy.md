# data/legacy.json

The run boundary (ROADMAP §9, R102). WHY THIS EXISTS: R87 gave the endgame a stake and a sink and deferred the third part on purpose — an ending the player CHOOSES. Measured on today's tree across thirteen seeds, the county falls on median day 28.6 (24 at the earliest, 39 at the latest, and all thirteen get there), while a campaign is 180 days. So 151 days happen after the only thing the game calls an ending, and a campaign stops when the player gets bored rather than when they decide it is finished. The R102 entry itself said median day 35-54 and "~130 days"; both numbers predate R94, R138, R154 and R157, each of which made the player stronger, and both moved the wrong way. THE BOUNDARY ALREADY EXISTED AND WAS EMPTY: `startNewRun` carried `settings`, `guidesSeen` and `ui` — a sound toggle and some read receipts — so retiring a finished county produced a run identical to the first and merely emptier. A new game plus that carries nothing is a new game. EXACTLY ONE THING, and the word doing the work is exactly: carry nothing and the ceremony is a lie, carry two and a legacy system becomes a save editor one milestone at a time. `maxPicks` is here rather than in the engine so the ceremony can say it out loud, and `applyLegacy` REFUSES a second pick rather than replacing the first, because refusing is the behaviour a player can understand from one try. WHAT IS DATA AND WHAT IS ENGINE: the kinds, their prose and the ceremony's words are data, so a fourth kind is an object in `kinds` and no engine edit. What a kind MEANS is `carries`, and campaign/legacy.js throws on a `carries` it does not implement rather than quietly keeping nothing — R41's training.json lesson, where a silent fallback ran the whole game on default tuning for a milestone. THE OFFER IS DERIVED FROM THE RUN: you cannot keep a veteran you never built or a bloodline off an empty ranch, and an unfinished run offers nothing at all, because the pick is what FINISHING buys. WHAT A VETERAN KEEPS is drawn at what it IS versus what it HAD — its anatomy, name, scars and temperament travel; injuries, settling clocks, its place in a stable that no longer exists, the GRADES its parts were cut at and the LEVEL it earned all stay behind. R102 originally put grade and level on the keeping side, and R172 measured the bill: the campaign walker could not start from a second run at all until `campaignWalk` took a `from` state, and the first thing it showed was that a second run carrying its best creature took the county on median day 25.33 against 30.83 — against a control, a second run packing NOTHING, that reproduced its first run's day EXACTLY on all fifteen seeds, so the movement was the creature and not the seeded stream. A1's wall (one body against the second node, the invariant R106 and R119 were each built around) read 0% for a first run and a median 81% for a second. THE COST IS THEREFORE DATA, in `cost`: `resetsGrades` and `resetsLevel` are flags the engine reads and `line` is what the ceremony prints, so a different price is a JSON edit. The founder's grade itself is NOT typed here — it is `crateGrade` in data/starters.json, one constant with one home (R157). Priced, the second run takes the county on day 30.92 against a 30.83 control and beats that control on 6 of 15 seeds, which is a coin flip: R119's founding-lab rule — the choice changes WHICH creature, never HOW MUCH — now holds at the run boundary too. WHAT A CROSSING RE-STAMPS is `CARRY_CLOCKS` in campaign/legacy.js, and `tools/smoke.js` requires it to name every clock-shaped field a WALKED creature actually holds: R102 shipped a hand-typed delete list of six names of which FOUR were not fields, so the real settle clock rode through and creatures arrived mid-settle a median 19.4 days (max 38.4) into a run that had not started. `openedBy` names the save field that opens the ceremony, so a future ending that is not dominion is a data edit here too.
