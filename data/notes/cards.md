# data/cards.json

The specimen card (ROADMAP §9, R108). WHY THIS EXISTS: there was no way to take a creature out of this app. Verified before a line was written — the only `download` the game has ever produced is the save file (`save/slots.js`), `navigator.share` appears nowhere in the tree, and `creaturePortrait` has always returned a standalone `<svg>` string that nothing ever handed to anybody. A player could spend a campaign assembling a genome and could not show it to the person sitting next to them.

ONE FILE, NO BACKEND, AND THE MILESTONE DOES NOT ADD ONE. A card is a single self-contained SVG: the portrait the game already draws, the name, the lab, the grade letters, the stat line, the moves, a short printed genome code, and the genome itself as JSON in `<metadata>`. That is the whole transport. Two people with no server between them can put their creatures in a room because the creature IS the file.

TWO DOORS, BECAUSE A FILE IS A THING PHONES LOSE. `<metadata>` is the good door — exact, no parsing of drawn text. The printed code is the other one: `frame~socket.part.grade~…`, restricted to the unreserved URL set so it survives a chat app, a URL bar and being read down a phone. `readCard` tries the metadata first and falls back to the printed code, so a card that came back as a retype still builds the same creature.

THE STAT BLOCK IS NOT IN THE FILE, AND THAT IS THE POINT. A card carries a GENOME; `unitFromGenome` — the same physiology `campaign/rivals.js` builds its specimens with — derives the numbers on every read. A saved stat block would be a promise about a fight the engine has stopped making: the first balance pass after the card was written would make it a lie, and the card would keep insisting. The round-trip gate checks hp, power, armor, speed, stamina and the moveset against the original creature for exactly this reason — a genome that survives while the numbers drift is a card lying about the fight it is offering.

VALIDATION IS R108'S OWN, BECAUSE R114 HAS NOT SHIPPED. This is the first feature in the game that takes a file from ANOTHER PERSON, and R114 has already measured that 263 `.name` fields in this tree are interpolated unescaped. Waiting for that milestone would mean opening the hole it exists to close, one milestone early. So `splice/card.js` escapes the five characters on everything it draws, and `safeText` — one function, so there is one thing to audit rather than two — strips markup characters from a stranger's name and lab and bounds them to `card.nameLimit`. A creature called nine kilobytes is a layout attack as well as a script one.

REFUSALS ARE CONTENT. Every sentence the importer can print lives in `refusals` here, including the ones a player only sees when something has gone wrong — a refusal is the most-read prose in an import feature and CLAUDE.md's "all content is data" has no carve-out for error text. They refuse BY NAME: "this card names a part nobody has: `unicorn_horn`, in the head socket" is actionable, and "invalid card" is not. `{name}`-style fillers are substituted by one function (`say`), and a key the data forgets falls back to the key rather than to `undefined`, so a half-written data file still refuses.

A GRADE IS CHECKED AGAINST THE STAIRCASE, NOT AGAINST A LIST THIS FILE KEEPS. `visitingSpecimen` reads `GRADE_INDEX` from `splice/grades.js`, so retiring a grade refuses the cards that name it — R72's rule, which this would otherwise have quietly broken by hard-coding four words.

ONE VISITOR AT A TIME, and that is a bound rather than a convenience. R91's rule is that every list in the save has a ceiling somebody chose, and a board of accepted cards would be an unbounded list fed by other people's files, which is the worst kind of unbounded list there is. `state.visiting` holds one genome; the next card accepted shows the last one out, the way a guest book has one page open.

THE EXHIBITION HAS NO PURSE, and it is the one encounter in the game that does not. `reward: 0`, `tier: null`, `capturable: false`, no notoriety, nothing bagged. The point of the fight is that two people can compare creatures, not that one of them farms the other — and an imported unit whose numbers a stranger chose must not be able to pay. It rides as an INLINE unit object in `waves` (the shape `rivalEncounter` already uses) because a visitor is nobody in `content.enemies` and never should be.

AN UNBUILDABLE VISITOR STOPS BEING OFFERED RATHER THAN THROWING. `visitingEncounter` re-validates on every read, so a card accepted before a part was retired quietly loses its row instead of taking the War Room's render down with it. R79's rule.

ADDING TO THIS FILE IS A JSON EDIT. The palette, the card's size, the two limits, the exhibition's words and every refusal are here; `splice/card.js` carries defaults for all of them so a missing key changes nothing rather than drawing `undefined` on a card somebody is about to hand to a friend.
